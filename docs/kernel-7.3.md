# Переход на Linux 7.3

Работа 28 октября 2026. Ветка `mainline-7.3`, issue #31, #32, #33.

## База

- Раньше порт собирался из `TeamYogaBlade2/linux` `blade/v7.1`. Этот форк
  отличается от Linux 7.1 только кодом MT6589 и arm32 (`diff -rq` с
  `linux-7.1.tar.xz`): для SM6115 он равен 7.1.
- Теперь база — релиз 7.3 с kernel.org (18 октября 2026), архив и sha256 в
  `kernel/README.md`. 7.3 — последний релиз mainline на 28 октября,
  стабильная ветка тогда — 7.2.13.
- В `sm6115.dtsi` между 7.1 и 7.3 добавился только узел Venus
  (`video-codec@5a00000`, выключен). `sm6115p-lenovo-j606f.dts` не менялся.

## Патчи

| Патч | Что стало на 7.3 |
|---|---|
| `0009` eGPIO | убран: функция в mainline с 7.2 (`pinctrl-sm6115.c`, `egpio_enable`) |
| `0016` fastrpc | переписан: в 7.3 fastrpc получил poll-режим и новый `ctxid` |
| `0017` psci-cpuidle | оставлен: 7.3 всё ещё пробует psci-cpuidle один раз, без патча ядра только в WFI |
| `0018` (новый) | очередь ESD-проверки тача с `WQ_PERCPU`: 7.3 предупреждает об очереди без `WQ_PERCPU`/`WQ_UNBOUND` |
| `0019` (новый) | WCD937x добавляет компоненты SoundWire из work, см. ниже |
| `0020` (новый) | QRTR держит рукопожатие HELLO как в 7.2, см. ниже |

Остальные патчи ложатся на 7.3 без изменений.

## Звук: WCD937x ждёт сам себя

На первой загрузке 7.3 звуковой карты не было:

```
wcd9370-codec sdw:3:0:0217:010a:00:3: Initialization not complete
wcd937x_codec codec: ASoC error (-110): at snd_soc_component_probe() on codec
```

Пробу кодека запускает последний добавленный компонент RX/TX, и она ждёт
5 с инициализации TX-устройства SoundWire. Ядро SoundWire держит замок
устройства всю его `probe()` и при каждой смене статуса. Когда TX
добавлялся последним, его собственная проба держала его инициализацию:
отладочный `soundwire-bus.ko` показал «probe complete» TX только после
таймаута, и сразу за ним — инициализацию. Порядок RX/TX в 7.3 стал другим.
`0019` добавляет компоненты из work после `probe()`. Перепривязка
`snd-sm8250` возвращает карту и без патча.

Одна загрузка после `0019` всё же была без карты, лог не сохранился
(issue #32).

## Wi-Fi: модем висит на загрузке (QRTR)

Wi-Fi (WCN3990) работает через модем. На 7.3 он часто поднимался к 75–78 с
вместо 35 с:

```
qcom_q6v5_pas 6080000.remoteproc: fatal error received: dog_hal_common.c:173:DOG detects stalled initialization
```

Модем стартует на ~34 с, объявляет в QRTR 2 службы из 42 и через 40 с
падает по сторожевому таймеру; после перезапуска всё приходит. Перезапуск
модема на живой системе (`rc-service rmtfs stop/start`) не зависал ни разу
(6 из 6), только холодная загрузка.

Ложный след: одна загрузка с `cpuidle.off=1` прошла чисто, следующая с ним
же зависла. Звук тоже ни при чём (с отключённым `snd_soc_sm8250` зависало).

В 7.3 переделано рукопожатие HELLO (`net/qrtr/af_qrtr.c`, `ns.c`): ядро шлёт
HELLO из work при регистрации конечной точки, до этого выбрасывает любые
другие пакеты к узлу (`-EAGAIN`, без повтора), а сервер имён больше не
отвечает на HELLO удалённой стороны. Проверка заменой только `qrtr.ko`:

| `qrtr.ko` | загрузок | зависаний |
|---|---|---|
| 7.3 как есть | 4 | 1 (до этого 3 из 5 на чистой сборке) |
| 7.3, ядро отвечает HELLO на каждый HELLO | 5 | 3 |
| `af_qrtr.c` и `ns.c` из 7.1 | 5 | 0 |
| 7.3 + `0020` | 5 | 0 |

Значит, виноват выброс пакетов до HELLO, а не потерянный HELLO. `0020`
отправляет такие пакеты, как 7.2, и снова даёт серверу имён отвечать на
HELLO. С ним Wi-Fi на 34–37 с. На 28 октября в net, net-next и linux-next
`af_qrtr.c` такой же, как в 7.3: исправления там нет.

## Проверено на чистой сборке

Сборка `build-kernel.sh` с нуля на нетронутом `linux-7.3`: тач, подсветка,
звук, микрофоны (DBMD8), датчики, Bluetooth, Wi-Fi, сеть по USB, ADSP/CDSP и
fastrpc, `cpuidle` (`cpu-sleep-0-0`, `cpu-sleep-1-0`, кластеры гасятся).
Android на `_b` после проб: `sys.boot_completed=1`. `0020` проверен
заменой модуля; образ из ветки с ним ещё не собирался.

## Открыто

- #32: карта звука на одной загрузке не появилась.
- #33: `reboot` из Linux примерно в 6 из 20 случаев приводит в Android;
  `adb reboot recovery` возвращает Linux.
- Камеры на 7.3 не проверены.
- `rtcwake` не ставит будильник: RTC PMIC только на чтение, сон не
  проверить по таймеру.
