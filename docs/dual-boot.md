# Двойная загрузка TB-J606L

Состояние на 26 октября 2026. Проверено на лабораторном экземпляре.

## Как устроено

| Что | Где |
|---|---|
| Android | слот B, как и был: `boot_b`, `dtbo_b`, `vbmeta_b`, `super`, `userdata` |
| Ядро Haltia | раздел `recovery_b` (образ boot v2: Linux 7.1, DTB J606L) |
| Корень Haltia | новый раздел `haltia` (LUN 0, около 38,5 ГиБ, ext4) |
| `userdata` Android | ужат до 64 ГиБ и отформатирован заново |

Активный слот не меняется: всегда B. Загрузчик (ABL) запускает `recovery_b`,
когда в разделе `misc` записано сообщение `boot-recovery` или при входе в
recovery кнопками. Иначе грузится Android.

Стоковый DTBO ABL применяет к любому DTB. Основной DTB меток производителя
не знает, и без доработки загрузчик отказывается его запускать. Поэтому
`kernel/dtb-overlay-sink.py` добавляет в DTB узел-приёмник с пустыми узлами
под все 192 метки стокового DTBO и `__symbols__`, указывающие только на них.
Оверлей ложится в приёмник и не трогает настоящие узлы.

## Переключение

- Из Haltia в Android: пункт «Android» (`haltia-reboot-android`), он снимает
  `boot-recovery` и перезагружает.
- Из Android в Haltia: вход в recovery (кнопками при включении или
  `adb reboot recovery`).
- Haltia остаётся системой по умолчанию, пока доходит до рабочего стола:
  при каждой загрузке `haltia-init` сначала снимает флаг, а сессия через
  минуту работы ставит его снова. Если Haltia не поднялась, следующая
  перезагрузка ведёт в Android.

## Что работает

USB (ACM-шелл и сеть NCM), UFS, кнопки питания и громкости, экран через
simpledrm на кадровом буфере загрузчика, `phoc` и оболочка Haltia.

Касание (Novatek NT36523W по SPI): прошивку контроллера `haltia-firmware`
берёт при загрузке из стокового `vendor_b`. Перо пока выключено.

Экран: MSM DRM (DPU, DSI, панель BOE NT36523W из дерева J606F), выход
`DSI-1`. Альбомный вид: phoc поворачивает вывод на 90°
(`/etc/haltia/phoc.ini`), касание идёт за встроенным экраном само. GPU
Adreno 610: стоковые zap-шейдер и `a630_sqe.fw` из `vendor_b`.

Wi-Fi (WCN3990): прошивку WLAN исполняет модем. Модем грузится из
стоковых образов `modem_b` (`haltia-firmware` копирует их в
`/lib/firmware/qcom/sm6115/LENOVO/J606L/`), `tqftpserv` отдаёт ему файлы,
`rmtfs` — копии EFS в `/var/lib/rmtfs` без записи (`-r`), так что
`modemst1`, `modemst2`, `fsg` и `fsc` не меняются. Калибровка платы —
стоковый `bdwlan.bin` (board id 0xff): в linux-firmware записи Lenovo_P11
нет. Время берётся по сети (ntpd); RTC PMIC только читается.

Bluetooth: WCN3990 на UART3 (`qcom,wcn3990-bt`), прошивки из
linux-firmware-qca. Своего адреса у контроллера нет: при загрузке ему
даётся постоянный адрес из серийного номера планшета (`10-bt-address`).

Батарея: датчик MM8013 на I2C0 (`mm8013`, загружается из
`modules-load.d`). Зарядку ведёт сам PMIC.

Зарядка от сети: контроллер USB-C FUSB302 на I2C0 (0x22) через TCPM,
только потребитель. Его `tcpm-source-psy-0-0022` (тип USB) показывает
`online=1` при подключённом кабеле, и оболочка не усыпляет планшет на
зарядке.

Bluetooth-звук: A2DP через `pulseaudio-bluez`, PulseAudio сам переключает вывод
на подключённые наушники (проверено 28 октября с Sony WH-1000XM4). Разъёма
3,5 мм у планшета нет; проводные наушники — через USB-C (#28).

Часы: RTC PMIC только читается. `swclock` держит время между
перезагрузками, ntpd поправляет его по сети. `haltia-init` удаляет кэш
зависимостей OpenRC: при часах «из прошлого» OpenRC иначе пропускает
службы (так однажды не стартовали `rmtfs` и Wi-Fi).

Сон: кнопка питания гасит подсветку, через 30 с без зарядки оболочка
усыпляет систему (s2idle), кнопка питания будит. Касание, Wi-Fi и USB
после пробуждения работают (USB — с патчем 0004).

Чехол: датчик Холла на GPIO 36 даёт `SW_LID` (`gpio-keys-lid`), будит
систему только при открытии. Реакции оболочки на чехол пока нет: elogind
настроен на `ignore`, потому что разовый сон elogind на SM6115 прерывается
через несколько секунд трафиком модема. Гасить экран по чехлу должен цикл
сна оболочки (`haltia-sleep` в haltia-de/shell).

Подсветка: SGM37604A на I2C1, драйвер `sgm37604a` (только яркость,
режимы оставляет загрузчик), `/sys/class/backlight/sgm37604a`, 0–4095.

phoc рисует через GPU (GLES2, freedreno). Масштаб 1 задан явно: MSM
сообщает настоящий размер панели, и phoc сам выбрал бы масштаб 2.

Звук, динамики: четыре усилителя AW88258 на I2C0 (сброс GPIO 42) за портом
LPASS primary MI2S (линия данных SD1). ADSP даёт службы APR (q6afe, q6asm),
карта — машинный драйвер RB2 (`Lenovo-TB-J606L`), UCM `HiFi`/`Speaker`,
PulseAudio. Профили регистров усилителей — стоковый
`vendor/firmware/awinic/aw882xx_acf.bin`; профиль рассчитан на TDM на
четыре слота, драйвер переводит усилители в стерео I2S: левые динамики
играют левый канал, правые — правый.

Датчики: на ядре датчиков ADSP (SSC) — акселерометр, гироскоп, освещённость,
приближение. `hexagonrpcd` (SensorPD) отдаёт DSP его библиотеки из `dsp_b`,
конфиги из `vendor_b`, реестр из `persist` (монтируется только на чтение) и
описание платы (`socinfo`: IDP, SoC 444); без последнего реестр падал вместе
с ADSP. `iio-sensor-proxy` берёт их через libssc. Матрица установки
акселерометра делает «normal» альбомным видом, `transform_offset=270` в
`/etc/haltia/device.conf` поворачивает книжную панель; `haltia-rotate`
поворачивает экран за планшетом. Правило polkit разрешает сессии занять
датчик. Сервер RootPD не запускается: вместе с SensorPD рано на загрузке он
ронял систему в аварийный режим.

Микрофоны: два аналоговых микрофона на АЦП голосового DSP DSPG DBMD8
(SPI5, прошивки `dbmd8_va_fw.bin` и параметры шумо- и эхоподавления ASRP из
`vendor_b`). Драйвера ядра у DBMD8 пока нет: служба `dbmd8`
(`haltia-dbmd8`) загружает его через spidev, запускает юзкейс Lenovo
«melon GA 2-mic AEC 16 kHz» и держит включённым. Звук идёт по I2S (DBMD8 —
ведущий, 16 кГц) на линию данных 1 порта `SEC_MI2S` (запись MultiMedia2,
устройство UCM «Mic»). Смещение микрофонам даёт кодек WCD937x на SoundWire,
пока идёт запись.

Не работает пока: наушники (WCD937x уже поднят, нужны маршруты),
раздача питания по USB-C (OTG), основная камера.

Bluetooth-звук: A2DP через `pulseaudio-bluez`, PulseAudio сам переключает вывод
на подключённые наушники (проверено 28 октября с Sony WH-1000XM4). Разъёма
3,5 мм у планшета нет; проводные наушники — через USB-C (#28).

Часы: RTC PMIC только читается и идёт с 1970 года. `haltia-rtc` при загрузке
ставит время RTC плюс смещение, которое `ntpd -S` сохраняет после каждой
синхронизации и служба — при выключении (`/var/lib/haltia/rtc/offset`).

Сон: s2idle через хук `/usr/lib/haltia/hooks/suspend` (`rootfs/haltia-suspend`),
будят двойной тап, кнопка питания и открытие чехла. Закрытый чехол
(датчик Холла `gpio-keys-lid`) гасит экран через `haltia-sleep` (haltia-de/shell#87),
logind крышку не трогает. Глубокий сон SoC (`vlow`/`vmin` RPM) пока
не достигается. Подробности — [sleep.md](sleep.md).

Фронтальная камера (OV8856) работает через CAMSS и libcamera: см.
[camera.md](camera.md).

## Почему USB молчал раньше

На холодной загрузке DWC3 не поднимался (`failed to enable ep0out`): в
дереве J606F нет `qcom,select-utmi-as-pipe-clk`, а SS PHY выключен. Через
`fastboot boot` USB иногда работал, потому что загрузчик оставлял ядро
контроллера настроенным. Свойство добавлено в `kernel/sm6115-lenovo-j606l.dts`.
Командная строка также несёт `clk_ignore_unused pd_ignore_unused`.

## Почему экран гас

Пока дисплей шёл только через simpledrm, модуль `dispcc_sm6115` не видел
потребителей (MDSS был выключен в DTS) и выключал домен питания MDSS:
экран гас, хотя ядро и сессия работали. С включённым MSM DRM у него есть
потребитель. Командная строка несёт `regulator_ignore_unused`.

## Вход кнопками

Питание + громкость вниз открывает меню загрузчика. Кнопками громкости
выбрать «Recovery mode», питанием подтвердить: запускается Haltia.
«START» запускает систему по умолчанию.

## Аварийный ход

Резерв критичных разделов — `backups/` (вне Git). EDL: `adb reboot edl`,
`qdl --storage=ufs prog_firehose_ddr.elf ...`. Стоковый `recovery_b`
возвращается из резерва через `fastboot flash recovery_b`.
